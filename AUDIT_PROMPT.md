# Промпт для полного QA-аудита сайта «Столовка»

Ты работаешь с уже функционирующим проектом школьной столовой. Главный приоритет — НЕ СЛОМАТЬ рабочую логику, Supabase, отзывы, админку, каталог, избранное, поиск и подбор комбо.

## Режим работы
1. Сначала изучи весь проект и составь карту: HTML, CSS, JS, Supabase-запросы, авторизация, отзывы, админка, каталог, избранное, комбо, localStorage.
2. До правок зафиксируй рабочее поведение и сделай резервную копию файлов.
3. Не делай массовых рефакторингов ради красоты кода. Меняй только то, что доказанно является багом, дублированием, мусором, лишней сложностью или узким местом.
4. После каждой группы изменений повторно проверь затронутые сценарии.
5. Не менять структуру БД и RLS без отдельной необходимости и без явного объяснения.

## Безопасность и устойчивость
Проведи ТОЛЬКО защитную проверку. Не выполняй реальную DDoS-атаку, не используй чужие ботнеты, прокси/VPN для обхода ограничений и не создавай вредоносный трафик. Проверки нагрузки выполняй только локально или на специально предназначенном staging-окружении с ограниченной безопасной интенсивностью.

Проверь:
- устойчивость интерфейса к очень быстрому повторному клику по кнопкам;
- двойную/тройную отправку форм;
- повторную отправку отзывов;
- частые переключения вкладок;
- быстрый ввод/стирание в поиске;
- открытие/закрытие «Подробнее» много раз подряд;
- открытие нескольких блюд подряд;
- работу при медленной сети и временной ошибке Supabase;
- поведение при отсутствии интернета;
- пустые/частичные/неожиданные данные из БД;
- длинные названия, описания и отзывы;
- мобильные размеры экрана;
- keyboard navigation / Escape / focus;
- обычных пользователей, которые кликают по всему подряд;
- ботов с точки зрения rate limit, повторных запросов и спама;
- работу за VPN/прокси как обычного клиента, без обхода защит;
- XSS-инъекции через отзывы, имена, описания и поля админки;
- утечки service_role / секретов / паролей в клиентский код;
- ошибки RLS и неверные права SELECT/INSERT/UPDATE/DELETE;
- отсутствие бесконечных циклов, лишних timers и повторных listeners;
- race conditions в асинхронных запросах;
- повторные сетевые запросы, которые можно безопасно кэшировать;
- тяжёлые blur/backdrop-filter/анимации, вызывающие лаги;
- загрузку внешних изображений и шрифтов;
- ошибки при 404 картинок;
- CLS, скачки интерфейса и лишний scroll-jump.

## Код-аудит
Проверь весь HTML/CSS/JS на:
- дублирующиеся id;
- дублирующиеся функции;
- мёртвый код;
- неиспользуемые переменные;
- повторяющиеся CSS-правила;
- старые стили, которые полностью перекрыты новыми;
- копипасту одинаковой логики;
- слишком сложные функции;
- лишние DOM-перерисовки;
- innerHTML с неэкранированным пользовательским вводом;
- console errors / unhandled promise rejections;
- обращения к несуществующим DOM-элементам;
- сохранение неверных данных в localStorage;
- несовпадение полей frontend и Supabase.

## Функциональные сценарии
Обязательно вручную/автоматически проверить:
- главную;
- светлую тему;
- тёмную тему;
- каталог;
- категории;
- поиск, включая «сушняк», «катлета», «макороны»;
- «Подробнее»;
- отзывы;
- добавление, изменение и удаление собственного отзыва;
- избранное и удаление из него;
- случайное блюдо;
- подбор комбо по бюджету;
- открытие одного товара из комбо без потери самого комбо;
- недавно просмотренные;
- админ-логин;
- просмотр отзывов в админке;
- изменение блюда;
- изменение цены;
- добавление нового блюда;
- наличие/склад;
- сохранение изображения;
- ошибки Supabase.

## Требования к дизайну
Светлую тему не ухудшать.
Тёмная тема должна быть «тёплый осенний вечер», а не чёрный экран: тёмно-коричневый/кофейный базовый фон, более светлые карточки, заметные границы, кремовый текст, терракотовые и янтарные акценты. Все элементы должны хорошо отделяться друг от друга.

В отзывах использовать осенние листья вместо визуальных звёзд. Эмодзи/иконки должны быть декоративными и не мешать доступности.

## Производительность «Подробнее»
Панель блюда должна появляться мгновенно. Отзывы и вторичные данные разрешено подгружать после открытия. Используй безопасное кэширование и предварительную загрузку при hover/focus/touch, если это реально уменьшает задержку. Не блокируй открытие карточки ожиданием авторизации или сетевого запроса, если чтение публичное.

## Финальная проверка
После изменений:
- проверить синтаксис JS;
- проверить дубли id;
- проверить дубли function declarations;
- проверить целостность HTML/CSS;
- проверить основные пользовательские сценарии;
- перечислить все сделанные изменения;
- отдельно перечислить найденные, но НЕ исправленные риски;
- не заявлять о тестах, которые фактически не запускались.
