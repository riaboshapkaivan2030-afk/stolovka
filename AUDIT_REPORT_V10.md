# QA-аудит «Столовка» — V10

## Что проверено
- HTML/CSS/JS `index.html` и `admin.html`.
- Supabase-вызовы, RLS-зависимая логика клиента, отзывы, избранное, поиск, комбо, random dish, `Подробнее`, localStorage.
- Статический поиск дубликатов `id` и функций, таймеров, listeners, `eval`, `document.write`, service-role ключей.
- Сценарии из `AUDIT_PROMPT.md` в той части, которую можно безопасно проверить без реальной атаки на production.

## Исправлено
1. DOM XSS в подсказке поиска: пользовательский запрос больше не попадает в `innerHTML` неэкранированным.
2. Экранированы названия/описания блюд и другие динамические поля в карточках, spotlight, detail, combo, random и recently viewed.
3. Если CDN Supabase JS временно не загрузился, публичный сайт больше не должен падать целиком: включается резервный режим.
4. Анонимный Supabase-пользователь больше не создаётся на каждый обычный просмотр сайта. Anonymous sign-in выполняется только когда человек реально пытается отправить/удалить отзыв.
5. Убрана предзагрузка отзывов по простому hover: это снижает лишние запросы к Supabase и нагрузку от ботов/быстрого движения мышью. Изображение по-прежнему прогревается.
6. Защита от двойной/тройной отправки одного отзыва: повторный submit блокируется до завершения запроса.
7. Исправлено определение собственного remote-отзыва: форма умеет найти отзыв текущего пользователя в данных Supabase, а не только в старом localStorage fallback.
8. `Подробнее` открывается до обновления «Недавно смотрели»; работа с localStorage вынесена из критического пути открытия панели.
9. Запись в localStorage стала fail-safe: отсутствие/переполнение storage не должно ломать избранное, тему или открытие блюда.
10. Random и бюджетные комбо больше не выбирают блюда с `is_available=false`.
11. В админке рейтинг отзывов визуально приведён к листочкам 🍁/🍂.
12. В админке добавлена простая проверка типа/размера загружаемого изображения (до 12 МБ) и фильтр remote URL для фото.

## Найдено, но сознательно не переписано
- В `index.html` очень много каскадных/повторяющихся CSS-селекторов. Это техдолг, но массовая консолидация CSS сейчас рискованна и может дать визуальные регрессии.
- В проекте дублируется часть админской логики: встроенная admin-вкладка в `index.html` и отдельный `admin.html`. Удалять одну из реализаций без отдельного решения не стал.
- Supabase JS загружается с CDN по диапазону `@2`, а не по фиксированной версии. Это снижает воспроизводимость деплоя; менять версию без браузерного regression-test не стал.
- Публичная страница содержит встроенный fallback-каталог. При долгом/аварийном Supabase он может быть старее базы. Лучше позже заменить цены fallback на нейтральное состояние загрузки, но это требует отдельной UX-правки.
- Полноценный production E2E и нагрузочная атака не выполнялись. Реальный DDoS/ботнет-трафик намеренно не запускался.

## Что не обнаружено статически
- дубли HTML `id`;
- дубли function declarations;
- `eval()`;
- `document.write()`;
- `service_role` ключ в клиентском HTML;
- бесконечные `setInterval`.

## Рекомендовано следующим этапом
- Подключить репозиторий через GitHub-интеграцию, чтобы проверять точный HEAD репозитория, а не только присланный snapshot.
- Добавить безопасный staging и browser E2E (Playwright/Cypress) для кликов, mobile viewports и network throttling.
- Отдельно настроить серверный rate limit/anti-spam для review writes; frontend debounce не является защитой от ботов.
